## Intento inicial

Windows reconocía el teléfono como dispositivo de transferencia de archivos, pero ADB no lo detectaba. El usuario activó depuración USB y aceptó la autorización; ADB pasó a mostrar el teléfono en estado `device`.

La instalación mediante `adb -s SERIAL install -r APK` devolvió:

```text
Failure [INSTALL_FAILED_USER_RESTRICTED: Install canceled by user]
```

No se ejecutó el arranque después de este fallo. Se pidió habilitar «Instalar vía USB» y aceptar el aviso del teléfono. No se desinstaló ninguna aplicación ni se borraron datos.

El usuario confirmó que habilitó instalación USB y corrigió la fecha. Un segundo intento devolvió el mismo `INSTALL_FAILED_USER_RESTRICTED`. Después ADB cambió a estado `offline`; no fue posible obtener una captura válida del aviso. Se pidió reconectar y comunicar el mensaje visible. La instalación sigue sin confirmarse.

El usuario precisó que el teléfono pidió aceptar la instalación y no llegó a aceptarla. Reiniciar el servidor ADB no recuperó la conexión. Windows mostró «ADB Interface» y «Redmi 9A» con estado OK y código de problema 0; eso no demuestra estabilidad del enlace. Tras revocar/renovar autorización en el teléfono, el usuario confirmó la nueva autorización y ADB volvió a estado `device`.

Otro intento por ADB volvió a ser rechazado. Se copió el mismo APK a `/sdcard/Download/Dayflow-0.9.0.apk`: transferencia confirmada de 5.100.821 bytes. Se pidió instalarlo manualmente desde Archivos → Descargas para aceptar el aviso en el dispositivo. La transferencia no acredita instalación. La conexión volvió a `offline` al consultar el dispositivo; no se obtuvo una captura válida ni se verificó aún el paquete instalado.

El usuario encontró el APK y confirmó «la he instalado ya». Informó de un aviso de Google Play/Play Protect y lo describió como «Aplicación desconocida o recomendación de analizarla». No se dispone del texto exacto ni de captura, ni se interpreta como prueba de que se detectara código dañino o de que el análisis se haya completado. No se pidió desactivar Play Protect. ADB sigue `offline`, por lo que el paquete instalado no se ha contrastado mediante `pm path` o metadatos del sistema.

El reloj del teléfono devolvió `2022-10-31T12:51:51+0100`, incompatible con la fecha de la sesión. Se pidió corregirlo antes de pruebas de autenticación, sincronización y alarmas. El hecho de que los ajustes automáticos estén habilitados no acredita que la hora se haya sincronizado.
